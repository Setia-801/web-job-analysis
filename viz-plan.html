4 张图表回答 4 个求职问题

图表不是越多越好：每张图只回答一个问题，颜色只用来表达结论。以下是图表设计依据、可复用的绘图代码，以及从图中提炼的 4 条落地结论。

Matplotlib中文微软雅黑 数据源：jobs_clean.csv图表脚本：viz_four_charts.py
01

图表设计总览

先定问题，再定图型——每张图的类型、坐标轴与业务意义

图图型X 轴Y 轴回答的问题 / 业务意义
① 薪资分布直方图（分箱柱状） 月薪区间（分箱，众数段高亮）岗位数 这个岗位给多少钱？——看报价集中在哪一段，确定谈薪锚点；中位数、均值、P25–P75 放角标
② 技能覆盖水平条形图 岗位覆盖率（%）技能（按覆盖率降序） 技能该学什么？——覆盖率是「要求广度」，条末再标注薪资提升度，一张图同时看到入场券与加价项
③ 方向对比双轴组合图（柱 + 折线） 岗位方向左轴：岗位数；右轴：薪资中位数 网页制作和前端是一条赛道吗？——两根轴一对比，「岗位多 ≠ 给得多」一目了然
④ 学历门槛双轴组合图（柱 + 折线） 学历要求（按门槛从低到高有序）左轴：岗位数；右轴：薪资中位数 专科学历的投递空间有多大？——量化可投占比与学历溢价，回答能不能进、值不值
三条设计原则：① 一张图只回答一个问题，多余维度宁可拆图；② 颜色只编码「结论」——重点柱用主色、普通柱用浅色、正向溢价用绿、压价信号用橙；③ 图内数字标注克制，柱顶标一层就够，双轴图再加白色底衬防止文字压在柱子上看不清。

图 1 完整实现 —— 含两个易错点：单位混用陷阱与 transAxes 角标定位：

def chart_salary(df):
    """
    直方图（按区间分箱的柱状图）
      X 轴：月薪区间（由 salary_median 分箱得到）
      Y 轴：岗位数
      业务意义：看清报价集中在哪一段，确定谈薪锚点
    """
    s = df["salary_median"].dropna()

    # 分箱边界按这个岗位的实际薪资水平定：低薪密集、高端稀疏，
    # 所以区间不是均匀的 2K 一档，高端直接跳到 15K 以上
    bins = [0, 4000, 6000, 8000, 10000, 15000, 30000]
    labels = ["<4K", "4-6K", "6-8K", "8-10K", "10-15K", ">15K"]
    cnt = (pd.cut(s, bins=bins, labels=labels, right=False)   # right=False: [4000,6000)
           .value_counts().reindex(labels, fill_value=0))     # 空区间也要显示 0

    fig, ax = plt.subplots(figsize=(6.6, 3.8))
    setup_ax(ax)

    # 众数区间用主色高亮，其余用浅色——让读者第一眼看到「最多的那段」
    colors = [ACCENT if v == cnt.max() else ACCENT_L for v in cnt.values]
    bars = ax.bar(cnt.index, cnt.values, color=colors, width=0.62, zorder=3)
    for b, v in zip(bars, cnt.values):
        if v:  # 柱顶标数字；v=0 的柱不标，避免出现一排 0
            ax.text(b.get_x() + b.get_width() / 2, v + 0.3, str(v),
                    ha="center", fontsize=9, color=INK)

    # ⚠ 易错点：中位数 7275 是「薪资」单位，而 Y 轴是「岗位数」，
    # 千万不要 axhline(7275)——数值远超 Y 轴范围，bbox_inches='tight'
    # 会为了容纳这条线把画布撑到上亿像素。数值标注要么换轴，要么用角标。
    med, mean = s.median(), s.mean()
    ax.text(0.98, 0.95,
            f"中位数 {med:,.0f} 元\n均值 {mean:,.0f} 元\nP25–P75 "
            f"{s.quantile(.25):,.0f}–{s.quantile(.75):,.0f}",
            transform=ax.transAxes,        # 用轴比例(0~1)定位，与数据单位无关
            ha="right", va="top", fontsize=8.5, color=TEAL, linespacing=1.6)

    ax.set_title("薪资分布：报价集中在 4–6K，中位数被中端岗位撑住",
                 fontsize=11.5, color=INK, loc="left", pad=10)
    ax.set_xlabel("月薪区间（元）", fontsize=9.5, color="#6b7482")
    ax.set_ylabel("岗位数", fontsize=9.5, color="#6b7482")
    ax.set_ylim(0, cnt.max() * 1.25)       # 留出柱顶数字和角标的空间
    save(fig, "c1_salary.png")

双轴图的写法（图 3 / 图 4 通用） —— 柱 + 折线组合的关键在两个 ylim 要手动对齐：

def chart_direction(df):
    """
    双轴组合图：柱状（岗位数）+ 折线（薪资中位数）
      X 轴：岗位方向
      左 Y 轴：岗位数（柱）；右 Y 轴：薪资中位数（折线，twinx 生成）
      业务意义：验证「岗位多 ≠ 给得多」，直接决定投哪条赛道
    """
    g = (df.groupby("job_direction")
         .agg(n=("salary_median", "size"), med=("salary_median", "median"))
         .sort_values("n", ascending=False))

    fig, ax = plt.subplots(figsize=(6.6, 3.8))
    setup_ax(ax)
    ax2 = ax.twinx()                       # twinx：共享 X 轴的第二根 Y 轴
    ax2.spines["top"].set_visible(False)   # 第二轴同样要去掉顶边框

    bars = ax.bar(g.index, g["n"], color=ACCENT_L, width=0.5, zorder=3)
    line = ax2.plot(g.index, g["med"], color=TEAL, marker="o",
                    linewidth=1.6, markersize=5, zorder=4)

    for b, v in zip(bars, g["n"]):                       # 柱顶：岗位数
        ax.text(b.get_x() + b.get_width() / 2, v + 0.4, str(v),
                ha="center", fontsize=9, color=INK)
    for x, v in zip(g.index, g["med"]):                  # 折线点上方：薪资
        ax2.annotate(f"{v:,.0f}", (x, v), textcoords="offset points",
                     xytext=(0, 8), ha="center", fontsize=8.5, color=TEAL)

    ax.set_title("四个方向的岗位数与薪资：数量与报价明显倒挂",
                 fontsize=11.5, color=INK, loc="left", pad=10)
    ax.set_ylabel("岗位数", fontsize=9.5, color="#6b7482")
    ax2.set_ylabel("薪资中位数（元）", fontsize=9.5, color=TEAL)
    ax.tick_params(axis="x", labelsize=10)
    ax.set_ylim(0, g["n"].max() * 1.3)
    # 双轴图必须手动对齐两个轴的显示范围，否则折线会贴着柱子看不清
    ax2.set_ylim(0, g["med"].max() * 1.3)
    save(fig, "c3_direction.png")
调试时踩过的坑，写在这里防止再犯：中位数 7,275 是「元」，Y 轴是「条数」——把中位数用 axhline 画到岗位数轴上，bbox_inches='tight' 会为了容纳这条线把画布撑到上亿像素，导出一张全黑的图。规则：数值标注要么画在与自身单位一致的轴上，要么用 transform=ax.transAxes 按轴比例定位。
03

图表结果与业务结论

结论全部由脚本从数据实时计算——不是看图说话的手写数字

① 薪资分布图型：直方图X：月薪区间Y：岗位数角标：中位数 / 均值 / P25–P75
结论 1谈薪锚定中位数，投递设 5K 的过滤下限。报价最密集的是 4–6K 区间（35.7%），但全样本中位数有 7,275 元，P75 达 8,388 元。低于 5,000 元的岗位只占 9.5%——把它设为投递下限，几乎不损失机会，却能省下大量筛选时间；带着作品集去谈，期望薪资报 7–8K 有数据支撑，低于 6K 的 offer 要先问清岗位内容再决定。
② 技能覆盖 Top10图型：水平条形图X：岗位覆盖率（%）Y：技能标注：薪资提升度（绿=加分 / 橙=压价 / 灰=门槛）
结论 2CSS/HTML 练到「能干活」就停，把主力时间押给 JS → Vue → 组件库。CSS 覆盖 70%、HTML 覆盖 59%，提升度都≈0——它们是入场券，不学进不来，多学不加分。而 JS（+12%）、Vue（+16%）、uni-app（+20%）都有两位数溢价；组件库只被 11.4% 的岗位要求，溢价却高达 +44%，是回报率最高的一笔学习投资。PS/Figma 提升度为负，说明设计技能在这类岗位是基础项而非加分项，够用即可。
③ 岗位方向对比图型：双轴组合图X：岗位方向Y 左：岗位数Y 右：薪资中位数
结论 3同样的技能栈，优先投「前端开发 / 小程序」方向的岗位。网页制作 + 网页设计占了 61% 的岗位，中位薪资却只有 6,020–5,850 元；前端开发与小程序岗数量少，中位却达 8,450–8,725 元，差距 +44.9%。「岗位多」的地方竞争者最多、议价空间最小——把前端方向设为第一梯队，「网页制作」岗作为保底梯队，且其中「底薪+提成」形态的岗位要单独评估真实收入。
④ 学历门槛图型：双轴组合图X：学历要求（有序）Y 左：岗位数Y 右：薪资中位数
结论 4大胆投，但会筛。72.7% 的岗位专科可投；「学历不限」岗中位 7,200 元，甚至高于大专类岗位（6,800 元）——写「学历不限」的中小企业往往按能力定价，值得优先投。本科类岗位溢价 +22.1%，遇到技能匹配的本科岗也照投不误，学历筛的是简历不是能力。另外，标题含「零基础 / 包就业 / 学徒」的是培训广告（本样本剔除 3 条，占原始数据 5.4%），直接跳过，不要浪费投递次数。
数据来源于公开招聘页面（流程验证样本 44 条），仅用于个人学习与研究。
